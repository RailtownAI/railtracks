# Upgrading to 1.9.0

Railtracks 1.9.0 removes the legacy human-in-the-loop package and its local chat UI. Nothing in the framework used them anymore; the middleware verifiers replaced them.

!!! warning "1.9.0 is a minor release with breaking changes"
    Version pins such as `railtracks>=1.8` or `railtracks~=1.8` will pick up 1.9.0 automatically. If you still use anything below and are not ready to migrate, pin `railtracks<1.9`.

`railtracks.human_in_the_loop` never had a deprecation warning, so this is the first notice of its removal.

---

## Removed

| Removed | Replacement |
|---|---|
| `railtracks.human_in_the_loop` (`HIL`, `HILMessage`, `ChatUI`) | `pre_verifier` / `post_verifier` for approval gates. None for the browser chat UI. |
| `rt.interactive` and the `railtracks.interaction.interactive` module | None |
| `railtracks.interaction.local_chat` | None |
| `railtracks.exceptions.VisualExtraRequiredError` | None. Delete the handler. |

Any remaining reference to these names now fails: attribute access raises `AttributeError` and `from ... import` raises `ImportError`, so a module-level import breaks at import time even if the code never runs it.

Calling `local_chat` (through `rt.interactive.local_chat` or `railtracks.interaction.local_chat`) has raised `NotImplementedError` since 1.5.0, so no working code depends on it. Delete those references.

The `[visual]` extra is unchanged. The `railtracks viz` CLI still needs it.

### Approval gates move to the verifiers

`HIL` was an abstract two-way channel to a person (`connect`, `disconnect`, `send_message`, `receive_message`). If you used it to ask someone to approve a step, wrap that node with `pre_verifier` (to approve the call before it runs) or `post_verifier` (to approve its result). Each takes an `approve_fn`, sync or async, that returns a `Verdict`. The code that sent the request and waited for the answer moves into `approve_fn`.


`HILMessage` has no replacement. Use whatever type suits your channel inside `approve_fn`.

See [Verifiers](../agent_design/middleware/verifiers/overview.md) for the full API, and [`examples/human_in_the_loop/`](https://github.com/RailtownAI/railtracks/tree/main/examples/human_in_the_loop) for worked versions, including a chat-loop sketch.

### No replacement for the browser chat UI

`ChatUI` and the `chat.html` page it served are gone, with no replacement. If you depend on them, pin `railtracks<1.9` and open an issue describing your use case.

### `VisualExtraRequiredError`

It was raised only when `ChatUI` was imported without the `[visual]` extra. Nothing raises it now, so delete the import and any `except VisualExtraRequiredError` clause.
